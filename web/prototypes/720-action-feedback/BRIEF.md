## Decisions already made (implement these; do not re-decide)

**State model (#723).** Four states 待命 / 處理中 / 已完成 / 失敗. Runs are 處理中 carrying a phase: 產生中 → 文本生成中 → 子題生成中 (k/n) → 圖片生成中 → 審題中 → 改題中 → done|failed (a 人工審題修正 run: 修改中 → 審題中 → 改題中). 審題中/改題中 are the on-screen labels for the 驗證/修正 生成步驟. On-screen control labels are verb-specific (下載中…, 已下載, 產生中…). Invariants: every 處理中 terminates; a control in 處理中 is not re-enterable; class-4 local toggles (show answer/solution, disclosures, language switch) never enter the model. Stream starters (確定發送): today's immediate teardown stays; the acknowledgement is an animated HAND-OFF from the pressed control to the 生成進度列; the control's 處理中 ends at the first server event; the run surface narrates 已完成/失敗. Exports: 處理中 on the control → 已完成 persists until the NEXT INTERACTION (any pointerdown or keydown anywhere, or a route change; scroll/hover do not count); clicking while 已完成 starts a fresh 處理中. 重抽: the row's value dims and its button disables during 處理中; on return the row flashes ONCE regardless of whether the value changed; if identical, a short hint says the draw returned the same value (zh 「重抽結果與原值相同」). History paging: stale rows stay visible, dimmed, `aria-busy="true"`; pager buttons enter 處理中; layout stable; no skeleton. 失敗 content: short label + one line of reason (`ApiError.detail` if present, else a generic action line such as 無法產生 ODT 檔案) + retry on idempotent actions (exports, 重抽, paging, resolve).

**Notice location (#724).** 處理中 and 已完成 render ON THE CONTROL (label, icon, colour), `role="status"`. 失敗 renders as an inline `role="alert"` notice DIRECTLY BELOW the control's row, full width of the control's container, styled like the app's existing red `role="alert"` blocks, holding the reason and a retry, dismissed by ×, by a successful retry, or by pressing the control again; it does NOT clear on unrelated interaction. NO toast layer, no sonner. 重抽 failure: the existing resolver banner stays AND the failed row's button shows 失敗. Batch ODT partial failure: report ONCE naming the failed 題組, produce NO file. State labels are fixed i18n strings and carry `sentry-unmask`; reasons do not.

**Library and tokens (#725).** `motion` (npm package `motion`, import from `motion/react`) via `LazyMotion` + `domAnimation` (`m.` components, NOT `motion.`), for presence/layout only: QuestionCard list entrance, disclosures, the hand-off. `tw-animate-css` for class-driven control state swaps. Native CSS (`@starting-style`, `dialog:open`, discrete `display`/`overlay` transitions) for the DestructiveConfirm `showModal()` lifecycle, no JS wrapper. React Router `viewTransition` on links/navigate for route changes, feature-detected. Tokens: durations quick 150 ms / standard 320 ms / slow 560 ms / loop 2250 ms; easings signature `cubic-bezier(0.22,1,0.36,1)` (entrances and state changes), exit `cubic-bezier(0.64,0,0.78,0)`, loop `cubic-bezier(0.25,0.1,0.25,1)`; NO overshoot anywhere. Entrance = opacity 0→1 plus 8 px upward travel, standard duration, signature easing; lists stagger 40 ms per item capped at 400 ms total. Exits use the next-faster token than their entrance. Reduced motion: entrances/exits/state transitions collapse to an instant change (1 ms opacity), route cross-fades skipped, indeterminate indicators (shimmer, spinner) keep running but drop to an opacity pulse with no translation/rotation; the caret goes solid. `web/src/motion/tokens.ts` is the single source: it exports the values and a function that writes `--motion-duration-{quick,standard,slow,loop}` and `--motion-ease-{signature,exit,loop}` onto `:root`; call it in `main.tsx` before first render and in `web/src/test/setup.ts`; `index.css` maps them through `@theme inline` (`--duration-quick: var(--motion-duration-quick)` etc.) so `duration-quick` / `ease-signature` utilities work; `MotionConfig` reads the module directly. shadcn: init with the Vite target, Base UI, neutral base colour; DROP the `@fontsource-variable/geist` import (CJK renders on the system stack); remap `--primary` to the app's blue-600; leave the generated `.dark` block inert and pin `data-theme="light"` on `<html>`. Hand-off choreography: three beats, one direction of travel, at most one element in flight: the confirmation section exits DOWNWARD on the exit curve (quick) → the form section enters (standard) → the 生成進度列 highlights with a single background pulse and its running indicator switches on, starting 100 ms after the exit begins (standard); total under 600 ms; no auto-scroll.

**AICSS adoption (#726).** AICSS is a recipe source, NOT a dependency. Vendor exactly two keyframes into `web/src/motion/aicss.css`: `label-shine` (shimmer sweep of `background-position`, 300% background-size) and `caret-blink`, re-tokenised to the loop easing/duration tokens and the app colours (shimmer base blue-600, highlight blue-300). The header comment names github.com/kvnkld/aicss, commit 4556a918 and the MIT licence; ship the MIT text as `web/src/motion/LICENSE-aicss.txt`. No registry components, no `@aicss/react`, no Orbs, no Inter. One app-owned `Shimmer` span and ONE shared linear `Spinner` component that replaces the hand-rolled `animate-spin` ones you touch. 生成進度列 running state: remove ◐; the shimmer sweeps across the live text and appears NOWHERE else. Single-run breadcrumb reads 文本 › 子題 › 圖片 › 審題 › 改題; the live step gains 中 (文本生成中, 子題生成中 k/n, 圖片生成中, 審題中, 改題中) and shimmers; done steps green, pending grey; before the first pipeline event: 產生中, shimmered; batch: 「產生中 · 已完成 k / n」 shimmered; a modification run uses 修改 › 審題 › 改題. i18n: `statusbar.running` zh 生成中 → 產生中; EN strings unchanged (Generating / Verify / Correct). ProgressLog status line: the same phase label as the bar from one selector, with the shared spinner, no shimmer. AgentStatusPanel lanes: StatusDot becomes the shared spinner; panes stay `<pre>`; a caret sits at the tail of the active pane while streaming. QuestionCard in a batch: the in-flight card carries a phase chip (spinner + phase label) beside its result chips.
