# navigation guarding requires the data router

The 生成頁面 shows a 破壞性操作確認 before the user loses 未送出的輸入 or generated questions. In-page click handlers cover every exit we render ourselves — the back-to-subjects button, the history link, logout, clearing results, re-submitting — but they fundamentally cannot see the browser or hardware Back button, because that navigation never passes through our handlers. The `beforeunload` guard covers closing the tab, refreshing, and editing the URL, but it does not fire for history navigation inside a single-page app, because no document unload occurs. Back was therefore the one exit that silently discarded work with no prompt at all. We moved the app from the component router (`BrowserRouter` + `Routes`) to the data router (`createBrowserRouter` + `RouterProvider`), because `useBlocker` — the only supported way to intercept a router navigation — is available only under the data router.

## Considered Options

Living with the gap and relying only on the browser's close-and-refresh prompt was rejected because Back is a common and reflexive way to leave a page; it would discard 未送出的輸入 silently, leaving the guard visibly inconsistent — every exit we render asks for confirmation while the most instinctive one does not. Intercepting history events manually — listening for `popstate` and re-pushing a sentinel entry to cancel the navigation — was rejected because cancelling requires pushing the user's position back onto the history stack after the fact; that briefly changes the address bar, corrupts the forward history, and reimplements badly what the router already models properly.

## Consequences

Route definitions move out of `App.tsx` into a `RouteObject` array in `src/routes.tsx`, and the always-mounted chrome — the staging banner and the feedback button — becomes a pathless layout route rendering an `Outlet`, which is what keeps it present on every page. The router is created per `App` mount via `useMemo` rather than at module scope, because module scope captures `window.location` once at import time and would not survive mounting at a different URL. `useBlocker` becomes available to the 生成頁面. The page tests that mock the router continue to pass unmodified, because they mock `useNavigate` and `useLocation`, which behave identically under the data router. The change was verified instead by a new `App.routing.test.tsx` that drives real URLs through `history.pushState` and asserts every route, every auth redirect, and the shared chrome, and which passes unchanged across the refactor.
