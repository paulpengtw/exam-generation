# 數學 gains 文本 and 小題 via a paired 題組題 / sub_question_count boundary

數學 gains an optional generated 文本 and an optional `subquestions[]`; the 題組 path is governed by a bidirectional boundary. Supplying `sub_question_count` resolves `題型種類=題組題`, while a resolved `題型種類=題組題` derives `sub_question_count` when it was not supplied. A request resolved to `單一題` with no count remains the existing one-call path: one flat `題目` / `正確解題分析` result, with no `文本` key on the wire. The original #201/#203 decision treated the count as the opt-in switch; #401 deliberately broadens that decision to cover the resolved group branch as well. Neither side of the pair is allowed to stand alone: a `題組題` item must carry populated `subquestions`, and a flat item cannot carry a group count. For requests that still resolve to `單一題`, the new fields cannot change existing consumers, few-shot examples or tests merely by being added to the model; the deliberate exception is a bare request whose seed resolves to `題組題`, as recorded in the amendment below. The math `ExamQuestion` and `SampledParams` changes belong to #202 and #203; this ADR fixes the shape they must implement. The math prompt currently explicitly forbids `subquestions`, `核心問題` and `文本` (`src/context_builder.py:223-232`), so that instruction remains the flat-path rule until the group path is selected.

The 題組 path reuses the shared 文本生成器 → N 子題產生器 core in `src/common/generation_core.py:1-8`, parameterised by a math `SubjectGenerationSpec` in `src/common/subject_spec.py:134-179`. It will not be a math-specific single-call variant that happens to emit a `subquestions` array. ADR 0002 makes the exact 小題 count a 強制值: an over-long plan is truncated and a short plan is padded. That acceptance criterion is already enforced once in the shared core at `src/common/generation_core.py:181-193`; a flat call could not provide the same guarantee without re-implementing it and forking the prompt-assembly logic that 社會領域 and 自然科學 already share. Before #401, the math adapter and sampler treated the flat path as the default (`server/generate/subjects.py:835-871`); #401 now lets a resolved `題組題` enter this existing core whether the count was supplied or derived.

`text_word_limit` governs only generator-authored 文本. 社會領域 and 自然科學 currently fan the request-level value into each slot's config (`src/social_studies/cli.py:74-96`, `src/natural_sciences/cli.py:70-92`); 數學 will do the same once it has a generated 文本. A supplied `user_passage` is 釘選 and reaches the prompt verbatim (`src/context_builder.py:407-412`), so supplying `text_word_limit` together with it is rejected with HTTP 422. The limit has no referent for user-authored text: trimming it is the nonsensical case identified by #183, while silently ignoring the limit is the silent-discard behaviour #183 was filed against. The latter would also display a parameter on 發送前確認 that does not take effect, contrary to ADR 0001. The request model already routes subject validation errors through the HTTP 422 path (`server/generate/models.py:157-185`, `server/generate/routes.py:250-304`), so this relationship is a validation rejection, not a prompt hint.

The original #201/#203 rule was one-way: supplying `sub_question_count` implied `題型種類=題組題`. That implication is now bidirectional. If no `題型種類` is supplied, an explicit count still pins `題組題`; if it is supplied together with `題型種類=單一題`, the contradiction is rejected with HTTP 422. Conversely, after `selected_set_type` resolves to `題組題`—whether it was pinned by the count at `src/sampler.py:115`, randomly drawn at `src/sampler.py:117`, or explicitly supplied as `set_type`—the sampler derives a count at `src/sampler.py:120-121` when needed. This closes the staging inconsistency: `question_schemas.json:30-38` already makes `題組題` a legal math value and `src/sampler.py:108-110` can draw it, while the original math `ExamQuestion` and `SampledParams` design exposed only the flat shape (`src/schemas.py:99-145`) and the flat prompt forbade the corresponding fields. The paired values therefore select the representation and count together.

#201 covers exactly `text_word_limit` and `sub_question_count`. `question_word_limit`, `option_word_limit` and `subquestion_configs` remain out of scope and remain rejected by `_math_validate_params` (`server/generate/subjects.py:253-272`); per-小題 configuration for 數學 needs its own decision. There is also a real documentation contradiction left standing here: `CLAUDE.md:391` currently says the top-level 選項字數限制 (per-option A–D) is math-only even though `_math_validate_params` rejects `option_word_limit` outright. This ADR records that contradiction but does not resolve it; it needs its own issue. This ADR supersedes #183's reject-don't-implement direction only for `text_word_limit` and `sub_question_count`.

## Amendment — #401: a resolved 題組題 implies a count

#401 selected option 2: retain the 題組題 draw and derive the missing count. The sampler resolves `selected_set_type` first and then, only on the `題組題` branch, assigns `sub_question_count = rng.randint(3, 7)` when the caller did not supply one (`src/sampler.py:110-121`). This applies both when `rng.choice` draws `題組題` and when the caller explicitly supplies `set_type=題組題`; it is not a fix limited to the randomly drawn case. The result is a true bidirectional boundary: a supplied count implies `題組題`, and a resolved `題組題` implies a count, so no item can be labelled `題組題` while carrying empty `subquestions` (`tests/test_math_group_pipeline.py:314-351`).

The derived range 3..7 is deliberate. It matches the API's own bound at `server/generate/models.py:97` and `server/generate/routes.py:199`, where both declarations use `ge=3, le=7`, and it matches the validated 社會領域 range at `src/social_studies/sampler.py:86-87`. A derived count is therefore indistinguishable from a supplied count at the API boundary: the sampler cannot produce a value that the API would reject.

The behaviour change is deliberate. ADR 0014 as originally written guaranteed that 數學 generation would be byte-identical when `sub_question_count` was absent, and #203 was built to preserve that guarantee. Option 2 knowingly gives up half of it: a bare request whose seed resolves to `題組題` now generates a real 題組 where it previously generated a flat item. That satisfies #401's third acceptance criterion through the explicit “or the change to that is deliberate and documented” branch. The test that pinned the old decision, `test_math_flat_path_runs_when_drawn_題組題_but_no_sub_question_count`, was deleted and replaced by `test_math_drawn_題組題_without_count_now_produces_a_real_題組` (`tests/test_math_group_pipeline.py:277-311`). The old pin was a recorded decision now reversed, not an accident being cleaned up.

What survives unchanged is the single-question branch. The derivation consumes the RNG only on the `題組題` branch (`src/sampler.py:120-121`), so seeds that resolve to `單一題` produce byte-identical `SampledParams` and byte-identical output. The snapshot is pinned by `tests/test_math_group_pipeline.py::test_sample_params_preserves_single_question_snapshot_without_count` (`tests/test_math_group_pipeline.py:104-150`); the flat generation path remains isolated for that branch (`tests/test_math_group_pipeline.py:246-274`).

## Considered Options

**Always move 數學 to 題組 output** — This would change the wire shape for every existing request, including consumers, flat few-shot examples and tests. It would also make the current math prompt, which requires a flat result, false for requests that did not ask for a 題組. The opt-in boundary preserves compatibility and makes the new representation explicit.

**Keep rejecting both parameters** — This was the safe-looking #183 direction, but it leaves #201 without a usable design for the two requested capabilities and cannot make 發送前確認 describe a parameter that the system accepts. It is superseded only for these two parameters; the other rejected math parameters remain rejected.

**Add a math-specific single-call 題組 generator** — A single call that emits both 文本 and a `subquestions` array would duplicate the two-stage prompt contract and would need its own count enforcement. It could not inherit ADR 0002's truncate/pad guarantee without duplicating the shared-core logic, creating two implementations of the same 強制值.

**Trim the 釘選 user_passage to satisfy text_word_limit** — User-authored material is sent verbatim by design. Mutating it would violate that contract and make the limit act on text the generator did not author.

**Silently ignore text_word_limit when user_passage is supplied** — This preserves the text but makes a submitted setting a lie. It recreates the silent-discard failure from #183 and makes the confirmation screen show a setting that will not affect generation.

**Allow `sub_question_count` with 題型種類=單一題** — This leaves the representation contradictory: the request asks for a count of 小題 while selecting a flat single item, and the current schema has no place to represent the result. Pinning `題組題` or rejecting the explicit contradiction makes the wire shape deterministic.

**Stop drawing 題組題** — This is not a pure data edit. `QuestionSetType` is built from `question_schemas.json` by `src/schema_loader.py:44`, so deleting the `題組題` value would break the `QuestionSetType("題組題")` pin at `src/sampler.py:115`; removing it from the draw would also shift every seed's choice. It changes the schema and the RNG stream instead of resolving the missing count.

**Keep the draw but relabel the item 單一題** — This would preserve the random draw while mislabelling a generated 題組 as a flat item, or would require discarding the derived count and group fields. It violates the paired boundary and reintroduces the representation mismatch that #401 closes (`src/sampler.py:111-121`, `tests/test_math_group_pipeline.py:314-351`).

**Decide `subquestion_configs` and per-小題 數學 controls here** — That surface includes per-小題 題型, instructions, curriculum selections and word limits. It is larger than #201's two parameters and would conflate a representation decision with a separate configuration design, so it remains a future issue.

## Consequences

The math `ExamQuestion` gains `文本`, `核心問題`, `取材來源` and `subquestions[]`, all with empty defaults. The flat path must omit those empty group fields when serialized, so an item whose resolved type is `單一題` serializes exactly as today and in particular has no `文本` key. A request that omitted `sub_question_count` but resolved to `題組題` now has a derived count and uses the shared group path, so its wire shape is intentionally not the old flat shape. The group path populates the shared 文本 and the requested or derived 小題 shape; the math `SampledParams` carries the two new request settings needed to select that path and limit generated 文本.

The math verifier and corrector must both learn the 題組 shape. The sharpest risk is in `src/corrector.py`: its correction contract permits only the mutable list of fields and restores every field outside that list (`src/corrector.py:54-56`, `src/corrector.py:115-141`). If `subquestions` is not added to the preserved shape, a correction pass can silently delete every 小題 of a 題組. This is the highest-severity regression in the design and must be covered by a test. The verifier currently joins only top-level `題目` and `正確解題分析` for its prompt (`src/verifier.py:88-103`), so it likewise needs an explicit 題組-aware view of each 小題 and its answer.

數學 needs at least one 題組題 few-shot example. `data/few_shot/` currently contains only flat items, so the new path cannot rely on the existing examples alone to teach the parent 文本, 核心問題, 取材來源 and 小題 shape.

The web form must un-gate 文本字數限制 and 小題數量 for 數學. That means changing `supportsTextWordLimit` and its resolved-parameter gate in `web/src/components/ParamForm.tsx:1070-1072`, `web/src/components/ParamForm.tsx:1644-1679` and `web/src/components/ParamForm.tsx:2910-2922`, and removing the math strip in `web/src/utils/toGenerateParams.ts:41-64`. The 發送前確認 rows narrowed by PR #200 must include math again: the current rows restrict both values to 社會領域/自然科學 at `web/src/components/ParamForm.tsx:1868-1892`. ADR 0001's rule means the rows must show the resolved values that will actually reach the opted-in path.

This ADR originally recorded two current statements in `CLAUDE.md`: the assertion that math keeps a flat output structure (`CLAUDE.md:102`) and the assertion that top-level 文本字數限制 is 社會領域/自然科學-only because 數學 has no 文本 field (`CLAUDE.md:391`). They are corrected by #202 and #203, not by this ADR. #401 adds the sampler-boundary correction recorded above: a request without `sub_question_count` can now resolve to `題組題`, derive a count, and enter the shared core, so the old statement that current flat behaviour is the only implemented behaviour is historical and no longer applies. `CLAUDE.md:102` is now corrected by this task to reflect the 題組題 derived-count path, so the contradiction no longer stands.

Batch dedup continues to work for the top-level math `出題概念` and `學習內容` because `extract_math_prior_scope` reads those fields (`src/common/batch_dedup.py:46-61`). It will not capture per-小題 scope inside a 題組. That is a known and accepted limitation of this design.
