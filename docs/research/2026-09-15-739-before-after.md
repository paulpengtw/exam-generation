# Issue #739: generation and modification evidence seams

This frontend prefactor implements the bounded preparation for OpenSpec
`per-question-live-progress` task 6.3 and design decision 6. The shared status
bar takes tagged `RunEvidence`; generation card fields cross the explicit
`projectGenerationCardEvidence` seam. Modification decoding is pure and its
hook retains lifecycle, admission, guards, result replacement and error routing.

No v2 behavior, legacy attribution fix, or resolver/model/policy change is
included. There are no Python, SSE protocol, i18n, DOM, or guard changes.
The `generate-v2` tag reserves an entry point and renders only the existing
aggregate running line. It carries no protocol fields.

## Conservative choices and deviations

- The supplied green baseline did not reproduce on the first two full runs;
  the unrelated failures and subsequent passing run are recorded above.
- `subject` is optional on the status bar, retaining its existing math default,
  so the modification caller can drop the dummy subject as requested.
- The detailed slice-4 contract takes precedence over the broader wording
  about tagged cards: `GenerationCardEvidence` has exactly five named fields,
  without an added profile key. The status bar inside QuestionCard consumes
  tagged modification evidence. HistoryDetail is left as is because it builds
  card props from a stored record, the legacy/history path.
- A hook regression test additionally preserves malformed `result` events
  clearing any earlier buffered result. Decoder tests also cover invalid
  question values and the existing empty-error fallback.
- Slice 5 uses a temporary documentation reproduction test for its red/green
  step because the slice changes only documentation and verification evidence.

No implementation work from the bounded brief is intentionally deferred.
The broader OpenSpec v2 and legacy attribution work remains outside this change.
