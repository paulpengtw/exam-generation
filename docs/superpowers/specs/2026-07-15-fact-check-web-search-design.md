# Spec: Web-search fact-check pass for 時事 social-studies questions (issue #104)

## Why

The verifier judges internal consistency only — a question can cite a fabricated election result or UN resolution and pass, because the passage it is checked against was generated by the same pipeline.

## Decision

Use the **Anthropic native `web_search` server tool** only. The issue's Tavily fallback is dropped (one provider until proven insufficient). Social studies only. Additive: the teacher verification pass is unchanged; fact-check runs after it for 時事-flagged questions.

## Design

### LLM client (`src/llm_client.py`)

`generate_with_tools(system, user, tools, purpose, max_iterations=3) -> tuple[str, list[Citation]]`: a `messages.create` loop passing `tools=[{"type":"web_search_20250305","name":"web_search","max_uses":N}]`. With the server tool, Anthropic executes searches server-side; the loop mainly handles `pause_turn`/continuation and extracts final text + citation blocks. Config (`src/config.py`): `web_search_provider: "anthropic" | "none"` (default `none` — opt-in), `web_search_max_uses` (default 5).

### 時事 detection (`src/social_studies/fact_check.py`, new)

`is_current_events(question) -> bool`: heuristic OR of — 公民 學習內容 codes in a configured list; 核心問題/文本 matching `近年|最近|今年|去年|本屆|現任|當前`; explicit flag when provided. Pure function, unit-testable.

### Fact-check pass

`fact_check_question(client, question) -> FactCheckResult` prompts: 驗證下列時事陳述是否屬實，必要時使用 web_search 查證，回傳 JSON `{verified, citations, issues}`. Wired into `src/social_studies/verifier.py::verify_question`: when provider enabled AND `is_current_events(question)`, run after the teacher pass; `fact_check.verified is False` forces `passed=False` and appends issues to `details` (so the existing correction loop sees them).

### Schemas (`src/social_studies/schemas.py`)

`FactCheckResult(verified: bool, citations: list[str], issues: list[str])`; `VerificationResult.fact_check: FactCheckResult | None = None`.

## Error handling

- `web_search_provider="none"` (or missing tool support at the endpoint) → skip with one logged warning; verification result unaffected.
- Tool-loop exhaustion or malformed fact-check JSON → treat as inconclusive: log, set `fact_check=None`, do not fail the question (fail-open — a broken search must not block generation).

## Testing

- Mocked `messages.create` returning tool-use/pause then final text → loop completes, citations extracted.
- 時事 question + mocked contradiction → `passed=False`, `fact_check.verified=False`.
- Non-時事 question → zero fact-check calls.
- Provider `none` → clean skip, no crash.
- `is_current_events` heuristic table tests.

## Out of scope

Caching search results; corrector auto-rewrite using citations (follow-up); math/NS fact-check; frontend citation UI.
