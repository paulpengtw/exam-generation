## 3. Frontend: container-start hook script

- [ ] 3.1 Create `web/docker-entrypoint.d/50-follow-release.sh` (or place it at `web/scripts/50-follow-release.sh` if a `scripts/` directory convention is preferred — check the repo's existing Dockerfile COPY patterns and match them). The script MUST: use only `#!/bin/sh` at the top — do NOT use `set -e` (the nginx entrypoint already runs under its own `set -e`, so any non-zero exit from the hook would abort the container before the hook can reach its own `exit 0`); guard every command that can fail with `|| …` so non-zero exits are suppressed; end with an explicit `exit 0` as the last line. Specifically: exit 0 immediately with one log line if either `GATEWAY_FOLLOW_URL` or `GATEWAY_CONTROL_TOKEN` is unset; extract `build_id` from `/usr/share/nginx/html/build-meta.json` using `sed -n 's/.*"build_id": *"\([^"]*\)".*/\1/p'` guarded so that a missing or unparsable file logs a message and exits 0 without a network call; POST to `$GATEWAY_FOLLOW_URL` with `curl --silent --max-time 8 -H "X-Gateway-Control-Token: $GATEWAY_CONTROL_TOKEN" -H "Content-Type: application/json" -d "{\"build_id\": \"$BUILD_ID\"}" "$GATEWAY_FOLLOW_URL"` retried up to 3 times with a 2 s sleep between attempts (inline loop, not `--retry`, to preserve the `|| exit 0` semantics); log the HTTP response; on any failure log and continue to `exit 0`. The total wall-clock time under repeated failure MUST be well under 30 s. Make the file executable (`chmod +x`). Verify by running the shell hook test created in task 4.1.

- [ ] 3.2 Add to the final (`nginx:alpine`) stage of `web/Dockerfile`: `COPY web/docker-entrypoint.d/50-follow-release.sh /docker-entrypoint.d/50-follow-release.sh` and `RUN chmod +x /docker-entrypoint.d/50-follow-release.sh` (the `COPY` sets permissions but `chmod` is an explicit safeguard). The build stage is unchanged. Verify by building the image locally (`docker build -f web/Dockerfile -t web-test .`) and confirming the file exists at `/docker-entrypoint.d/50-follow-release.sh` with execute permission (`docker run --rm web-test ls -la /docker-entrypoint.d/`).
