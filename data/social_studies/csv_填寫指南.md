# CSV 填寫指南：社會科命題系統

> 本指南適用對象：負責填寫與維護下列 CSV 檔案的研究人員。
> 所有填寫內容**直接影響語言模型（LLM）的行為**，從命題角色設定到題目條件、
> 課程錨定、難度校準，每一欄位都會被直接或間接注入 LLM 的提示詞中。
> 修改 CSV 後，**下一次執行系統即生效**，無須重新編譯。

---

## 一、前言：系統如何使用 CSV

本系統以 ICCS 2022 公民與社會評量架構與 108 課綱社會領域為基礎生成試題。每次生成一道題時，
系統會執行以下流程：

```
CSV 檔案
  └─ 系統讀取（執行時直接解析）
       ├─ 系統提示（System Prompt）── 給 LLM 的「角色設定 + 課程背景」
       └─ 使用者提示（User Prompt）── 給 LLM 的「本題指定條件 + 範例」
            └─ LLM 生成題目草稿
                 └─ 驗證迴圈（最多 3 次修正）
                      └─ 輸出 JSON 題目
```

**資料檔案對提示詞的分工：**

| 檔案 | 注入位置 | 影響類型 |
|------|---------|---------|
| `curriculum/schema_meta.csv` | 系統提示＋使用者提示 | 決定性（每次都注入） |
| `curriculum/schema_parameters.csv` | 使用者提示 | 隨機抽樣後注入 |
| `curriculum/內容領域_mapping.csv` | 抽樣器＋提示組裝 | 將學習內容代碼錨定到 ICCS 內容領域 |
| `curriculum/learning_performance.csv` | 系統提示 | 決定性（整批注入） |
| `curriculum/learning_content.csv` | 系統提示 | 決定性（整批注入） |
| `few_shot/few_shot_examples.csv` | 使用者提示 | 隨機抽樣 1–2 則 Channel-1 範例 |
| `few_shot/process_exemplars/*.json` | 子題使用者提示 | 依認知歷程注入 Channel-2 過程範例 |

> **格式規則（適用所有檔案）**
> - 儲存格式：UTF-8（Excel 存檔請選「CSV UTF-8 (逗號分隔)」）
> - 多值欄位分隔符：**分號 `;`**（勿用逗號，避免與 CSV 格式衝突）
> - 含逗號的長文字會由系統自動加引號處理，無需手動操作
> - 空白列會被忽略，不影響讀取

## 二、逐檔說明

### 2.1 `curriculum/schema_meta.csv`

**用途：** 設定此次部署的學習階段與年級範圍。

**欄位：**

| 欄位名稱（`欄位` 欄） | 範例值（`值` 欄） | 說明 |
|---|---|---|
| `學習階段` | `第四學習階段` | 注入系統提示與使用者提示 |
| `grades` | `7;8;9` | 用分號分隔的整數年級清單 |

#### `學習階段`, 影響兩處提示詞

1. **系統提示**第一行：
   > 「你是一位資深的 108 課綱社會領域命題教師，專門為 **{學習階段}**（{年級清單}）的學生設計…」

   這決定了 LLM 的**整體命題角色設定**。若改為「第五學習階段」，LLM 會以高中生為對象設計題目。

2. **使用者提示**的「指定條件」區塊：
   > 「年級重心：{抽樣年級}年級（**{學習階段}**）」

   每道題抽樣時會再次看到此標籤，強化年級對焦。

#### `grades`, 影響三處

1. **系統提示**年級清單文字（如「7年級、8年級、9年級」）
2. **隨機抽樣**：每道題的年級從此清單中隨機選取一個
3. **CLI 指令**的 `--grade` 可選值範圍

> ⚠️ `grades` 只能填整數（1–12），分號分隔，如 `7;8;9`。
> 填入範圍外的值（如 `13`）會導致系統找不到對應的學習內容。

### 2.2 `curriculum/schema_parameters.csv`

**用途：** 定義社會科命題的 live 參數類別、可選值及其說明文字。

**欄位：**

| 欄位 | 說明 |
|------|------|
| `類別` | 固定為下表的 live 類別之一 |
| `value` | 此選項的值（中文或英文名稱） |
| `instruction` | 該選項的補充說明；**非空時直接注入使用者提示** |

#### Live 類別及其在提示詞中的角色

| `類別` | 注入位置 | 抽樣規則 |
|--------|---------|---------|
| `情境` | 使用者提示 `## 條件補充說明` | 每題隨機選 **1 至全部** 個 |
| `題型種類` | 使用者提示 `## 條件補充說明` | 固定為 `題組題` |
| `題型` | 使用者提示 `## 條件補充說明` | 依小題指定或從四種格式抽樣 |
| `認知歷程` | 使用者提示 `## 條件補充說明` | 每個小題一個 ICCS bucket |
| `內容領域` | 使用者提示 `## 條件補充說明` | 每題組一個 ICCS 內容領域 |
| `科目` | 使用者提示 `## 條件補充說明` | 歷史、地理、公民與社會或跨科 |
| `題目內容類型` | 使用者提示 `## 條件補充說明` | 每題組一個值；共六種，見下文 |
| `難度` | 使用者提示 `## 條件補充說明` | 每題組一個值 |

#### `value` 欄的重要性

`value` 的所有值在系統啟動時會被建立為**動態列舉（Enum）**，作為抽樣的選項池。

> ⚠️ **若 `value` 填入重複值，後者覆蓋前者。若類別下無任何 value，系統啟動時會報錯。**

#### `instruction` 欄如何進入 LLM 提示

當某個 `value` 被隨機抽到時，其對應的 `instruction` 文字會**逐字注入**使用者提示：

**情境、題型種類、題型、認知歷程、內容領域、科目、題目內容類型、難度** → 注入格式：
```
## 條件補充說明

  - **情境（公共）補充**：{instruction 內容}
  - **題型（選擇題）補充**：{instruction 內容}
  - **認知歷程（Reasoning and Applying–Interpret information）補充**：{instruction 內容}
  - **內容領域（Civic Participation）設計指引**：{instruction 內容}
```

若 `instruction` 為空，該條目不會出現在提示詞中（區塊可能整個省略）。

> 💡 **建議**：`instruction` 應寫成對 LLM 的**具體設計指引**，而非對研究者的說明。
> 例如：「以報章社論或公告為文本素材，避免使用教科書式口吻」
> 而非：「這是公共情境類型」

### 2.3 `curriculum/learning_performance.csv`

**用途：** 提供社會領域的學習表現標準，讓 LLM 了解各學習階段的能力指標，
校準題目的認知需求層次。

**欄位：**

| 欄位 | 說明 |
|------|------|
| `學習階段` | 如 `第四學習階段`；可填入多個階段（不同列） |
| `編碼` | 學習表現代碼，如 `1a-IV-1`、`2b-IV-1` |
| `說明` | 該代碼的完整文字描述 |

#### 注入系統提示的效果

所有列資料會**整批序列化為 JSON** 注入系統提示的以下區塊：

```
## 課程綱要參考

### 學習表現標準

{整個 learning_performance.csv 的 JSON 結構}
```

LLM 能透過此內容了解「這個年段的學生預期具備什麼能力」，從而：
- 設計符合認知層次的題目難度
- 對應適合的認知歷程 bucket
- 避免題目超出或過低於目標年段能力

> ⚠️ 若此檔案為空（僅有標題列），系統提示會顯示：
> 「（課程綱要資料待研究人員補充至 data/social_studies/curriculum/）」
> LLM 仍可生成題目，但缺乏課程錨定，難度與能力對應準確度較低。

**建議填寫範圍：** 至少填入第三、四、五學習階段的表現標準，讓 LLM 能理解前後銜接脈絡。

---

### 2.4 `curriculum/learning_content.csv`

**用途：** 提供社會領域的學習內容（知識點）清單，讓 LLM 了解各年級應學習的具體主題，
確保題目緊扣課程範圍。

**欄位：**

| 欄位 | 說明 |
|------|------|
| `年級` | 如 `7年級`、`8年級`；注意需含「年級」兩字 |
| `編碼` | 學習內容代碼，如 `地Aa-IV-1`、`歷Ba-IV-1`、`公Bc-IV-1` |
| `學習內容條目及說明` | 該代碼的完整課程說明文字 |
| `備註` | 選填；如教學提示、跨科連結等（同樣會注入，請填有用內容或留空） |
| `對應學習表現` | 用 `;` 分隔的 `learning_performance.csv` 編碼，如 `1a-IV-1;3b-IV-1` |

#### 注入系統提示的效果

所有列依年級分組，**整批序列化為 JSON** 注入系統提示：

```
## 課程綱要參考

### 學習內容

[
  {"年級": "7年級", "學習內容": [{"編碼": "地Aa-IV-1", "學習內容條目及說明": "...", ...}]},
  {"年級": "8年級", "學習內容": [...]},
  ...
]
```

LLM 透過此內容能：
- 以正確的社會科知識內容設計文本素材（歷史、地理、公民）
- 避免題目涉及未教過的知識
- 在跨年級整合時有所依據

> ⚠️ `對應學習表現` 中的編碼若與 `learning_performance.csv` 對不上，
> 不影響系統運行，但 LLM 無法在兩張表之間建立關聯。
> 建議保持兩張表的編碼一致。

---

### 2.5 `curriculum/內容領域_mapping.csv`

**用途：** 提供學習內容代碼與四個 ICCS 內容領域的核准對照。抽樣器會用它限制公民與社會／跨科題組的公民學習內容池；歷史、地理題組仍使用自身的課綱代碼，但提示會保留內容領域的主題鏡頭。

**欄位：**

| 欄位 | 說明 |
|------|------|
| `編碼` | `learning_content.json` 中的學習內容代碼，例如 `公Cc-Ⅳ-1` |
| `內容領域` | 一個或多個 ICCS 值，以 `;` 分隔 |
| `備註` | 研究人員用的對照說明，不直接取代課綱文字 |

四個 `內容領域` 值為 `Civic Institutions and Systems`、`Civic Principles`、`Civic Participation`、`Civic Roles and Identities`。若新增或修正公民代碼，必須同步維持此表與 `schema_parameters.csv` 的四個值一致。

### 2.6 `few_shot/few_shot_examples.csv`

**用途：** 提供人工撰寫的優良題目範例，讓 LLM 模仿其格式、文體與難度。
這是**對 LLM 生成品質影響最直接、最立竿見影的檔案**。

#### 欄位總覽

| 欄位 | 填寫規則 | 說明 |
|------|---------|------|
| `範例編號` | 字串，同一題組所有列相同 | 分組識別碼；**跨例不重複** |
| `題目內容類型` | 一個值，填首列 | Channel-1 抽樣鍵；須與 `schema_parameters.csv` 的 value 完全一致；同組後續列可留空 |
| `description` | 短文字，填首列 | 範例標題，注入提示詞時顯示 |
| `情境` | 分號分隔 | 填首列；如 `個人;公共` |
| `題型種類` | 固定 `題組題` | 填首列 |
| `題型` | 一個值 | 題組層級預設格式；實際每小題格式填 `小題題型` |
| `認知歷程` | 每個小題一個值 | 填在對應小題列；只能使用四個 ICCS bucket |
| `內容領域` | 一個值 | 題組層級欄位，填首列；只能使用四個 ICCS 內容領域 |
| `核心問題`、`文本`、`取材來源` | 填首列 | 題組共用的核心問題、素材與來源 |
| `小題序號`、`小題年級`、`小題科目` | 每小題一列 | 小題的順序、年級與科目；多科目用 `;` 分隔 |
| `核心素養`、`學習內容`、`學習表現` | 每小題一列 | 以 `;` 分隔多個代碼；學習內容可寫成 `編碼:說明` |
| `出題概念`、`小題題型`、`答案`、`答案解析` | 每小題一列 | 小題設計、四格式題型、正答與解析 |
| `評分規準` | 每小題一列 | 開放式建構反應題填 JSON rubric；其餘格式填空陣列 |
| `題目` | 每列一個題目元素 | 首列＝文本素材；後續列＝各小題 |
| `正確解題分析` | 每列一個解析 | 與小題列對應；文本素材列留空 |
| `chart_spec` | JSON 字串 | 需要共用視覺素材時填首列；小題專屬素材放在 JSON 的小題欄位 |

正式檔案第一列標題固定為：

```text
範例編號,題目內容類型,description,情境,題型種類,題型,認知歷程,內容領域,核心問題,文本,取材來源,題目,正確解題分析,小題序號,小題年級,小題科目,核心素養,學習內容,學習表現,出題概念,小題題型,答案,答案解析,評分規準,chart_spec
```

#### 四種題型與原生計分

同一題組可混用下列四種 `小題題型`；不要新增已退役的封閉式建構反應題：

| 題型 | 題面與欄位要求 | 計分 |
|------|----------------|------|
| `選擇題` | 題目含 A–D 四個選項；`答案` 填單一字母；`評分規準` 為空陣列 | 0/1：答對 1 分、答錯 0 分 |
| `開放式建構反應題` | `答案`、`答案解析` 與 `評分規準` 必填；rubric 每個分數級距附 `規準說明` 與 1–2 個 `學生作答實例` | 0..N，可部分給分；依每題專屬 rubric |
| `拖放題` | 只能用於 `target_surface=數位`；輸出 `interaction`，含 `draggables`、`targets`、`correct_mapping`、`exact_match`、`shuffle_draggables` | 預設每個正確配對 1 分；`exact_match=true` 時全對才得 `max_score` |
| `滑桿題` | 只能用於 `target_surface=數位`；輸出 `interaction`，含 `min`、`max`、`step`、`unit`、`correct_value`、`tolerance` | 0/1：作答值落在 `correct_value ± tolerance` 內得 1 分 |

互動題的 `interaction` 是權威答案資料；`答案` 仍填給人閱讀的配對或數值說明。紙本題組不可填 `拖放題` 或 `滑桿題`。

#### 長格式行結構（同一 `範例編號` 的多列構成一道題）

```
範例編號 │ 題目                    │ 正確解題分析
─────────┼────────────────────────┼────────────────────────
EX-001   │ 【文本素材正文…】       │ （留空）
EX-001   │ 問題一：…(A)(B)(C)(D)  │ 答案：(B)。理由…
EX-001   │ 問題二：請說明…        │ 滿分（代號2）：…；部分得分（代號1）：…
```

**讀取邏輯：**
- `題目` 陣列 = 該 `範例編號` 下所有非空的 `題目` 格，**依列順序排列**
- `正確解題分析` 陣列 = 所有非空的 `正確解題分析` 格，依列順序排列
- 元資料（情境、題型…）從**首列**讀取，後續列的這些欄可留空

#### `題目內容類型` 與範例目錄

`題目內容類型` 只能填下列六值：

| 值 | 使用時機 |
|----|----------|
| `純文字` | 只用文字素材；不得輸出 `chart_spec` |
| `含圖片` | 需要圖片式視覺素材，如地圖、圖解、廣告或表單 |
| `graphs/charts/tables` | 需要統計圖、圖表或表格；資料寫入 `chart_spec` |
| `customized` | 使用者自訂素材類型；不由抽樣器隨機選取 |
| `混合` | 同時需要文字與非文字素材；非文字部分以 `chart_spec` 描述 |
| `數位閱讀` | 以網頁、搜尋結果或社群介面呈現的數位素材；依目標卷面使用互動或 HTML 描述 |

Channel-1 JSON 範例放在 `few_shot/<題目內容類型>/` 目錄；`graphs/charts/tables` 會使用同名的巢狀目錄。CSV 仍放在 `few_shot/` 根目錄，系統依 `題目內容類型` 欄位讀取對應題組。尚未有範例的鍵會只使用條件說明，不會阻塞命題。

> 每次生成題目時，系統會從目前指定的 `題目內容類型` 範例中隨機選 **1–2 則**注入使用者提示的 `## 參考範例` 區塊。每個 JSON 檔以一組計算抽樣機率；CSV 則以每個 `範例編號` 一組。

#### `few_shot/process_exemplars/`：Channel-2 過程範例

Channel-2 不按 `題目內容類型` 抽樣，也不與 Channel-1 混成同一組。子題 prompt 先帶入題組的 `內容領域`，再依該小題的 `認知歷程` bucket 選一筆過程範例；新增範例時請以 **（內容領域，認知歷程）** 配對設計題幹，檔案則按四個 bucket 分檔。這些 JSON 由 `src/social_studies/process_exemplar_loader.py` 即時掃描。

每個檔案可使用下列格式；`內容領域` 是供研究人員檢查配對的標籤，`bucket` 必須是四個 live bucket 之一：

```json
{
  "bucket": "Reasoning and Applying–Interpret information",
  "exemplars": [
    {
      "內容領域": "Civic Participation",
      "科目": "公民與社會",
      "題幹": "根據兩項公共資料，判斷哪一項最能支持居民參與決策？",
      "選項": {"A": "資料甲", "B": "資料乙", "C": "兩者皆非", "D": "無法判斷"},
      "答案": "B",
      "rationale": "說明學生必須同時讀取資料並套用該認知歷程，而非只辨識字面。"
    }
  ]
}
```

每筆至少要有非空的 `題幹`、`選項`、`答案`、`rationale`；`選項` 可為物件、陣列或字串。四個 bucket 是：`Knowing–Defining and Describing`、`Knowing–Illustrating with examples`、`Reasoning and Applying–Interpret information`、`Reasoning and Applying–Relate or Integrate`。

#### `chart_spec` 填寫格式

`chart_spec` 欄需填入合法的 **JSON 字串**（整個 JSON 寫在同一儲存格）。
有兩種模式：

**統計圖表（折線圖、長條圖、圓形圖、箱型圖）：**
```json
{"render_mode":"chart","chart_type":"line_chart","title":"圖表標題","data":{"x":[2000,2005,2010],"series":[{"name":"A組","values":[10,20,30]}]},"labels":{"x":"年份","y":"數值"}}
```

**HTML 排版素材（表格、地圖、廣告、表單、網頁）：**
```json
{"render_mode":"html","title":"素材標題","description":"詳細描述版面內容、欄位結構、資料來源","data":{"key":"value"}}
```

> 💡 `render_mode:"html"` 時，`description` 欄位內容會傳給 LLM 生成 HTML 圖像，
> 因此請盡量詳細描述版面結構、所含資訊與視覺風格。

#### 範例強烈影響以下面向

| 影響面向 | 說明 |
|---|---|
| **文本長度與複雜度** | LLM 傾向模仿範例的文字量與句型難度 |
| **題目數量** | 每題組的小題數量會對齊範例 |
| **給分說明詳細程度** | 解析的粒度（rubric 完整度）來自範例 |
| **題目主題** | 歷史、地理、公民的比例受範例比例影響 |
| **圖表複雜度** | `chart_spec` 的資料密度會被模仿 |

> ⚠️ 提示詞中已明確告知 LLM「**不要複製範例題目，必須原創**」，
> 所以範例提供的是「格式與水準的示範」，而非可直接使用的題庫。

## 三、填寫規則速查

| 規則 | 說明 |
|------|------|
| **多值分隔** | 一律用 `;`（分號），不用逗號 |
| **`範例編號` 分組** | 同一題組所有列必須填相同的 `範例編號`；不同題組不得重複 |
| **空白欄** | 各 CSV 中非首列的元資料欄可留空；系統會從首列讀取 |
| **空白列** | 完全空白的列會被忽略，不影響讀取 |
| **`value` 一致性** | `few_shot_examples.csv` 中填入的 `情境`、`題型`、`認知歷程`、`內容領域`、`題目內容類型` 值，**須與 `schema_parameters.csv` 的 `value` 欄完全一致**（包含全形/半形、空格），否則 LLM 可能收到矛盾訊息 |
| **Excel 存檔** | 請選「CSV UTF-8 (逗號分隔)」；避免選「CSV（MS-DOS）」 |
| **`chart_spec`** | 必須是合法 JSON（可用線上 JSON 驗證工具確認）；含中文時無需特別處理 |
| **`grades` 格式** | 純整數，分號分隔，如 `7;8;9`，不含空格 |
| **`備註` 欄** | 非空時**會被注入** LLM 提示，請填有意義的內容或保持空白 |

                      ▼

## 八、如何為範例題組加入圖檔

ODT 題本中的圖片（如地圖、統計圖、照片）已可自動注入 LLM 提示詞，作為多模態 few-shot 示範。

### 提取流程（只需執行一次，可重複執行）

```bash
uv run python scripts/extract_few_shot_images.py
```

此腳本將 `data/social_studies/example_exams/` 內的 6 個 ODT 依文件順序提取圖片，
輸出至 `data/social_studies/few_shot/images/<範例編號>/figure{N}.{ext}`，
並產生 `manifest.json` 記錄每張圖的對應說明文字。

| ODT 檔名 | 範例編號 | 圖片數量 |
|---|---|---|
| 1918年流感_20240319.docx.odt | ex001 | 3 |
| 電子垃圾_20240319.docx.odt | ex002 | 5 |
| 大城市病_20240319.docx.odt | ex003 | 2 |
| 移工_20240319.docx.odt | ex004 | 10 |
| 中華奧會魔法展_20240319.docx.odt | ex005 | 13 |
| 漠南咖啡豆_20240319.docx.odt | ex006 | 7 |

### 新增 ODT 題本

1. 將 ODT 檔放入 `data/social_studies/example_exams/`
2. 在 `scripts/extract_few_shot_images.py` 的 `ODT_TO_EXAMPLE` 字典新增對應（如 `"新題本.odt": "ex007"`）
3. 在 `few_shot_examples.csv` 新增對應行，`範例編號` 填入 `ex007`
4. 重新執行 `uv run python scripts/extract_few_shot_images.py`

> 圖片會在每次 LLM 呼叫時以 base64 形式注入提示詞，並無數量上限。
> 範例圖片較多的題組（如 ex005 有 13 張）在被 random 選中時會提高 token 用量。
